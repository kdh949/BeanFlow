# 고객센터 직접 처리 전환

[ADR-136](../adr/ADR-136-support-direct-processing.md), [ExecPlan](../exec-plans/completed/support-direct-processing.md).

고객센터 관련 쓰기를 중단하고 V91 DB migration → 새 서버 → 새 프런트 순서로 함께 전환한다.
신구 버전의 혼합 쓰기를 허용하지 않는다. 운영 배포 실행은 이 문서 작성과 별개다.

기존 승인·인증 이력은 보존한다. 이전 정책의 미실행 요청은 자동 승인하거나 변환하지 않는다.
같은 상담에서 새 요청을 작성하며 이미 실행한 금융/정보 변경을 중복 등록하지 않는다.
기존 금융 후속 작업은 기존 ID로 조회·복구한다. 요청/수정부터 15분 만료는 인증 재요구가 아니다.

새 업무는 SUPPORT_DIRECT 근거와 실제 actor/time을 확인한다. 본인확인 Provider는 더 이상
고객센터 시작 필수 조건이 아니며 생성/challenge/proof HTTP API는 410을 반환한다.
기존 조회/폐기와 과거 미확인 challenge 정리는 유지한다.

원문 응답 유실은 재전송으로 복구하지 않는다. 감사와 grant 사용 이력을 확인한다.
감사 실패/복호화 실패/현재 권한 회수는 원문을 반환하지 않아야 한다. 긴급 사후 검토와 보안 알림은
이전과 동일하게 후속 관리하되 다른 지원 업무의 시작 조건으로 사용하지 않는다.

검증 완료 전 운영 쓰기를 재개하지 않는다. 부분 적용 rollback을 기존 코드 재배포만으로 처리하지 않는다.
신규 직접 처리 행은 구버전이 해석할 수 없으므로 쓰기 중단 상태에서 정방향 수정한다.
